# outputs/metrics/

These files were generated by actually running the training and mapping
scripts on **synthetic placeholder data** (random noise, not real Sentinel-1
imagery), to prove the metrics/logging/serialization code works correctly.

- `unet_training_history.json`, per-epoch loss/IoU from the 2-epoch debug U-Net run
- `baseline_results.json`, RF/XGBoost metrics (accuracy, F1, IoU, Dice, Kappa, etc.) on synthetic features/labels
- `rf_feature_importance.json`, Random Forest feature importances on synthetic data
- `flood_dynamics_demo.json`, persistence/expansion/recession stats from the demo flood maps in `outputs/maps/`
- `train.log`, `train_baseline.log`, execution logs from those demo runs

**These numbers are meaningless as flood-mapping results**, they describe
how a model trained briefly on random noise behaves on more random noise,
not real accuracy on Kurigram District flooding. They exist solely to
demonstrate that the evaluation code executes and produces correctly
structured output. Per the project's scientific-integrity policy, no
numbers here should ever be quoted as real results, the real results table
in `README.md` correctly still says "to be generated after running the
pipeline" on actual Sentinel-1 data.

Once you train on real data, delete these files and regenerate.
